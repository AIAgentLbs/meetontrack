# Public MeetOnTrack 0.1.38 distribution acceptance

Date: 2026-11-24. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved on 2026-11-23 publishing the after-call fixes for Mac
and Windows with the website in the same run, then (2026-11-23, late) one
release, 0.1.38, instead of 0.1.37 and 0.1.38. This run installed 0.1.38 on
the owner's Mac (below), ran one short sound test there and moved that test
recording to the trash folder; it did not touch other recordings or the
Windows machine. Same process as [0.1.36](2026-11-23-0.1.36-distribution.md);
this record lists what differs.

Contents (`e3393bd..0ae06b1`): MEETONTRACK-188 (`0e29f21`, `95c7c7d`): a memo
sent to your own address is relabelled unread in the inbox. MEETONTRACK-189
(`7f39707`..`a7d2203`, merged as `409c0e4`): auto-record before the calendar
prompt, the mic watchdog, the far-end-not-recorded signal, retranscription and
delivery retries before Home shows the meeting with an action, stale markers,
the menu-bar alert. Two test-only follow-ups found by the release gates:
`c0dc4fb` (the capture-problems test took the recording id from SHA-1, which
the Security baseline's Semgrep blocks; it now reads the id from the archive
listing, the archive's ids are unchanged) and `2a5fbf3` (the delivery pill UI
script still expected the count the 189 step 7 replaced with names).
MEETONTRACK-191 (`67310cc`, `9157fdf`, merged as `0ae06b1`): no red
not-recording bar after a deliberate stop while the calendar event still
runs. User-facing summary in [v0.1.38](v0.1.38.md) and
[windows-v0.1.38](windows-v0.1.38.md). Built from `0ae06b1`.
