# Public MeetOnTrack 0.1.26 distribution acceptance

Date: 2026-11-10. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved building, publishing for Mac and Windows, updating the
website, installing on the owner's Mac and closing the shipped tasks on
2026-11-10 ("конечно, есть согласие"). Same process as
[0.1.25](2026-11-09-0.1.25-distribution.md), [0.1.24](2026-11-09-0.1.24-distribution.md)
and [0.1.22](2026-11-08-0.1.22-distribution.md); this record lists what differs.

Contents: Mac - MEETONTRACK-138 (an open but silent call-app output stream no
longer blocks the no-call-audio stop indefinitely; it defers it by one more
`silence_stop_minutes` window; `capture/` changed) and MEETONTRACK-132 (the
server reads the parent pipe from fd 0, so it no longer aborts with
`_enter_buffered_busy` when the app quits). Windows - MEETONTRACK-139 (the
recorder's `TrackWriter` closes its WAV file on every exit path). Shared web -
MEETONTRACK-141 (delivery health applies `<channel>_enabled_at`) and
MEETONTRACK-142 (one-click in-app update: the header shows "Version X
available" with an Install button that runs the tagged official installer,
waits for a recording to end and logs to `update.log`). Built from
`origin/main` `5465905331a782c47f067da190689fb6e39e6ead`; CI (python,
swift-build) and the Windows packaged candidate acceptance passed on that
revision.

## Immutable package identity

release mode at `5465905` (same `-Xcxx -isystem` libc++ flag; rpaths identical

differs only by line endings and the interpreter that built the pyc/vendor

## Explicit limits

No clean Mac and no audio hardware tests. Mac is ad-hoc signed and not
notarized; Windows is unsigned. Nothing installs by itself: the Install
button or the installer command starts it. Never restart an active recording
to update.
