# Public MeetOnTrack 0.1.28 distribution acceptance

Date: 2026-11-10. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved building, publishing on GitHub Releases and updating
the website on 2026-11-10, to ship the Mac in-app update fix (MEETONTRACK-142)
and then test the in-app update 0.1.26 to 0.1.28 on the Mac and 0.1.27 to
0.1.28 on Windows. The owner runs those updates himself, so this run did not
install 0.1.28 on the owner's Mac, did not touch its running 0.1.26 app or
config, and did not touch the Windows machine. Same process as
[0.1.27](2026-11-10-0.1.27-distribution.md); this record lists what differs.

Contents: commit `03d0bf5` (MEETONTRACK-142). The 0.1.27 in-app update from
0.1.26 failed safely on the Mac: macOS `pgrep`/`pkill` hide their own
ancestors unless given `-a`, so the update helper (a descendant of Capture)
and `install.sh` never saw Capture, the old app kept its port and the new
version could not answer. The helper now uses `pgrep -af`; `install.sh`, when
Capture is seen only as its ancestor, quits it by Apple Event (never SIGTERM,
so a recording gets its own question) and refuses as before when run from
Terminal next to a running Capture. 0.1.26/0.1.27 installs therefore heal:
their helper downloads `install.sh` from the `v0.1.28` tag. Built from
`origin/main` `03d0bf5d21f34889d530db01a76b4d1a02c39d51`; CI passed on that
revision.
