# MeetOnTrack 0.1.37

Technical beta for Apple Silicon with macOS 15+. Windows is a separate package.

- A memo you send to your own address now arrives in your inbox as unread,
  with the usual notification (MEETONTRACK-188). Gmail used to file it as
  already read, so it was easy to miss. The app's own Google sign-in now
  also asks for permission to change labels; until you sign in again, such
  a memo is still sent but may arrive as read.
- After a call, the memo reaches you more reliably (MEETONTRACK-189):
  - After a reinstall, automatic recording starts right away instead of
    waiting until you answer the calendar access question.
  - If the microphone does not start within 10 seconds, the app no longer
    freezes: the other side keeps recording and the app tells you the
    microphone did not start.
  - If the other side of the call is silent in the recording, for example
    because macOS lost the Screen & System Audio Recording permission, the
    recording is no longer cut off early. The app warns you during the call,
    and the memo and the report say first that the other side was not
    recorded.
  - A missing transcript is made again automatically and a failed memo
    e-mail is sent again, up to 3 times each. Only if that still fails does
    Home name the meeting, say what went wrong and offer an action when
    there is one you can take, such as Send again or opening the right
    permission.
  - A recording that was interrupted no longer holds every later memo back.
  - The menu bar icon turns red with a short line on top of the menu when
    memos were not sent, a recording was cut off, the other side is not
    being recorded or the microphone did not start.

Everything from 0.1.36 is included. The Capture app is rebuilt from this
revision and signed with the same MeetOnTrack certificate, so macOS keeps its
Screen & System Audio Recording permission.

Known: a few calendar sign-in states are still worded loosely, for example a
hint about the command-line tool when no sign-in is connected
(MEETONTRACK-184). After a reinstall Capture may not ask again for a
permission that macOS lost; the app now says when the other side or the
microphone is not being recorded, but check Microphone and Screen & System
Audio Recording in System Settings if it does (MEETONTRACK-185). Calendar
attendee names do not reach the report yet, and there is no preview of how
recipients will see the report (MEETONTRACK-179, 180). Send now does nothing on a report held for more than three days
(MEETONTRACK-178). Speaker separation may need manual correction.

The calendar is read from Google with your own sign-in and stays on this
Mac. Cloud AI receives the selected text context of the task it runs: the
memo is written from the meeting's calendar details and matching excerpts of
the sources you connected, and the check after the call sends the transcript
and the memo, only to the AI you chose, without web access. Cloud speech
recognition receives the audio only when you choose a cloud engine.
Google/SMTP/CRM integrations remain optional and off for new installations.
No usage-statistics feature is included.

## Update

On 0.1.26 to 0.1.36, use the Install button. Otherwise finish the call and quit
Capture, then run:

```sh
curl -fsSL https://meetontrack.com/install.sh | bash
```

Versions 0.1.10 and 0.1.11 do not show this update in the app: the
project's GitHub address changed, and those versions reject release pages at
the new address. Run the command above once. Versions 0.1.12 to 0.1.25 show
this update in the app but have no Install button yet; use the command.

The installer verifies the pinned package checksum and preserves recordings and
settings. It removes the previous version's program files only after the new
app's own service answers; otherwise it puts the previous version back.
Nothing installs by itself: the Install button or the command above starts
it. Version notifications are enabled by default and can be disabled in
Settings.
