# Public MeetOnTrack 0.1.29 distribution acceptance

Date: 2026-11-11. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved building, publishing on GitHub Releases and updating
the website on 2026-11-11. The owner runs the in-app updates himself, so this
run did not install 0.1.29 on the owner's Mac, did not touch its running
0.1.28 app or config, and did not touch the Windows machine. Same process as
[0.1.28](2026-11-10-0.1.28-distribution.md); this record lists what differs.

Contents: MEETONTRACK-143 (`3389953`, in-app update hardening: rollback quits
an unready new app by Apple Event, one install at a time and never over a
newer version, a stale live status no longer counts as recording, an
after-call update survives a restart), MEETONTRACK-144 (`8d547a8`, Windows:
one assistant window after an update, the recorder stays in the tray; the page
no longer treats the language and update-notice switches as unsaved edits)
and MEETONTRACK-145 (`dadd8bb`, auto-recorded browser calls named after the
browser, not "Google Chrome Helper (Ap"; `capture/` changed). Built from
`origin/main` `338995391222fca217641954f018371aa7b197da`; CI and the Windows
packaged candidate acceptance passed on that revision.

**Change from earlier releases (owner request):** both releases were
published as normal releases, not pre-releases. `v0.1.29` is marked latest;
`windows-v0.1.29` was published with `--latest=false`. Until now every release
after `v0.1.7` was a pre-release, so GitHub's `releases/latest` still
answered `v0.1.7`. Older releases were not edited. The in-app update checker
(`release_updates.select_release`) lists all releases and accepts
non-pre-releases on every channel, so this changes nothing for it.

## Explicit limits

No clean Mac and no audio hardware tests. Mac is ad-hoc signed and not
notarized; Windows is unsigned. Nothing installs by itself: the Install
button or the installer command starts it. Never restart an active recording
to update.
