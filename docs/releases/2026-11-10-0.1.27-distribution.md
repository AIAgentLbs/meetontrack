# Public MeetOnTrack 0.1.27 distribution acceptance

Date: 2026-11-10. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved building, publishing on GitHub Releases and updating
the website on 2026-11-10, to test the one-click in-app update
(MEETONTRACK-142) from 0.1.26. The owner updates his Mac himself with the
in-app Install button (that is the test), so this run did not install 0.1.27
on the owner's Mac or touch its 0.1.26 app or config, and did not touch the
Windows machine. Same process as [0.1.26](2026-11-10-0.1.26-distribution.md),
[0.1.25](2026-11-09-0.1.25-distribution.md) and
[0.1.22](2026-11-08-0.1.22-distribution.md); this record lists what differs.

Contents: version-only release. `git log ba6e277..origin/main` was empty;
between 0.1.26's source `5465905` and this source `ba6e277` only the 0.1.26
pins, notes, record and `docs/TODO.md` changed. No product change, no new
feature. Built from `origin/main`
`ba6e2778dfe91047f176587f6842985ff79246a8`; CI passed on that revision.

## Immutable package identity

Both packages embed application revision `ba6e277`.

Mac: `capture/` is unchanged since 0.1.26. The Swift release build at
`ba6e277` (same `-Xcxx -isystem` libc++ flag) was already up to date, so the
binary is the one built for 0.1.26 (rpaths identical); it was assembled as
0.1.27 (build 523). LocalVQE was reused from the published 0.1.26 archive
(SHA-checked), the Python runtime is the same clean uv `cpython-3.12.13`
scratch copy. Against 0.1.26 only Info.plist, the binary and the signature
(the ad-hoc signature is embedded and covers Info.plist), the shebang lines
of `f2py` and `numpy-config` and the numpy `RECORD` (temporary build path, as
in every build) differ.

Windows: recorder rebuilt from `windows/` (unchanged) in
[windows-candidate run 42781927336](https://github.com/AIAgentLbs/meetontrack/actions/runs/42781927336)
at `ba6e277` with version 0.1.27 (`managed.zip` SHA-256 `c3175335...`). The
release archive was composed locally from that `managed.zip` with
`package_candidate.py` under Homebrew Python 3.15, as before. Against 0.1.26
only the 5 rebuilt recorder files (they carry the version), `release.json`
and the `web/_vendor` pyc files differ. Against the CI-composed candidate it
differs only by line endings and the interpreter that built the pyc/vendor
files, as before.

`8ef85abebff138fb02ade1ffc527b9f4420c28c5`; Mac notes and `v0.1.27` tag/target

The 0.1.26 in-app updater downloads the installer from the release tag
(`raw.githubusercontent.com/AIAgentLbs/meetontrack/<tag>/...`) and checks
that it names that tag, so both tags were checked to carry these pins: at
`v0.1.27` and `windows-v0.1.27`, `install.sh` has `VERSION="v0.1.27"` and the
Mac SHA-256 above, and `scripts/windows/install.ps1` has
`$version='0.1.27-windows-beta.1'`, the `windows-v0.1.27` asset URL and the
Windows SHA-256 above. After publication both raw tag URLs answered HTTP 200
anonymously and were byte-identical to the tagged files.

Both releases were published as pre-releases (technical beta) on 2026-11-10
08:33 UTC. Both archives were downloaded anonymously from the normal
`releases/download` URLs after publication (HTTP 200) and matched these
checksums and sizes.

## Explicit limits

No clean Mac and no audio hardware tests. Mac is ad-hoc signed and not
notarized; Windows is unsigned. Nothing installs by itself: the Install
button or the installer command starts it. Never restart an active recording
to update.
