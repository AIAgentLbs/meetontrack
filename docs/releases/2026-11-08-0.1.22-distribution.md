# Public MeetOnTrack 0.1.22 distribution acceptance

Date: 2026-11-08. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved building, publishing for Mac and Windows, updating the
website, installing on the owner's Mac and closing the shipped tasks on
2026-11-08 ("Выпускаем"). Same process as
[0.1.21](2026-11-04-0.1.21-distribution.md); this record lists what differs.

Contents: Mac - MEETONTRACK-130 (the app resolves a busy assistant port
itself: a stale MeetOnTrack service, also a hung one or one started by hand
from a checkout, is stopped and the port taken over; a foreign program is left
alone and a free port is used, recorded in
`~/.local/share/meeting-copilot/server-port` for `install.sh` and
`meeting-copilot`), MEETONTRACK-125 (installer rollback restores the migrated
settings files). Shared web service - MEETONTRACK-126 (process group led right
after bind) and MEETONTRACK-124 (open AI sign-ins stopped on server
shutdown); both act on the Mac only, because Windows has no process group and
stops its server directly. Built from `origin/main`
`f5e1cb8871a403cab46d265c055767a29620f29e`.

## Immutable package identity

Both packages embed application revision `f5e1cb8`.

Mac: the Swift app was rebuilt in release mode from `capture/` at `f5e1cb8`
(`swift build -c release` with the `-Xcxx -isystem` libc++ flag only; rpaths
identical to 0.1.21) and assembled as 0.1.22 (build 484). LocalVQE was reused
from the published 0.1.21 archive (downloaded and SHA-checked), Sparkle is built
from the package, and the Python runtime is a clean uv `cpython-3.12.13`

the binary, the signature, `bin/meeting-copilot`, the four changed web files and
the shebang/RECORD lines of the numpy scripts (temporary build path, as in
every build) differ.

endings and the interpreter that built the pyc/vendor files, as before.

## Website

Website commit `59a488b`: `install.sh` and `docs/install.ps1` copied from the
app's `v0.1.22` and `windows-v0.1.22` tags, `test_installer.py` copied from the
app, EN/RU links and comparisons moved to 0.1.22, release notes added. All
Dockerfile checks passed locally (`test_installer.py` 22 tests,
`build-comparisons --check`, `test-comparisons`, `check-project-site`).

Deployment was delayed by GitHub's incident "Increase in timeouts for some
unauthenticated users" (2026-11-08, from 10:36 UTC). The site build downloads
its checksum-pinned screenshots from the app's `v0.1.9` release, and from the
Coolify host that route answered HTTP 502/504 or timed out (DNS and TCP were
fine; even `api.github.com/rate_limit` returned 504, so not a rate limit or an
outbound block). Four Coolify deploys of `59a488b` and two of `bfc4def`
(which added up to four download attempts per screenshot) failed at that step;
each failed deploy was discarded, so the live site kept serving 0.1.21 until
the fix. Website commit `3e1649e` falls back to the live site's own copy of
each screenshot, verified against the same SHA-256 pin, when GitHub cannot be
reached; Coolify deploy `j10visy59jwioakdfu40hzn9` then finished.

Live check after that deploy: `https://meetontrack.com/install.sh` and
`/install.ps1` are byte-identical (`cmp`) to the files at the `v0.1.22` and
`windows-v0.1.22` tags; `/` and `/ru/` each link 0.1.22 six times and no other
version; the screenshots answer HTTP 200. MEETONTRACK-124, 125, 126 and 130
were closed in the tracker after this check.
