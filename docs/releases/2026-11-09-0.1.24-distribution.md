# Public MeetOnTrack 0.1.24 distribution acceptance

Date: 2026-11-09. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved building, publishing for Mac and Windows, updating the
website, installing on the owner's Mac and closing the shipped tasks on
2026-11-09 ("Выпускаем 0.1.24? - да"). Same process as
[0.1.22](2026-11-08-0.1.22-distribution.md) and
[0.1.23](2026-11-09-0.1.23-distribution.md); this record lists what differs.

Contents: Mac and Windows - MEETONTRACK-137 (an automatically started
recording stops with `stop_reason` "no-call-audio" once the call track has
been quiet for `auto_record.silence_stop_minutes`, whatever the mic hears;
manual and paused recordings are not stopped by it; on the Mac a suspected
call-capture failure suppresses it, and backstop stops stand down until the
call app releases the mic). Windows - MEETONTRACK-136 (the recorder writes
`transcript.json`/`.md` without a UTF-8 byte order mark; the web service in
both packages reads recorder JSON as `utf-8-sig`, so meetings already on disk
are imported on the first pass after start). Shared web - the getting-started
AI card lists only tasks that cannot work or work with a limit (`429487f`).
Built from `origin/main` `41fa12ac7b6ce5b535b26a0c8bfb591d8c505619`; CI
(python, swift-build) passed on that revision.

## Known gaps

- The final transcript import and the no-call-audio stop were checked by unit
  tests, the Codex review of the fixes and the packaged installation on a
  Windows CI runner, not on a real Windows desktop or a real call. The owner
  updates the Windows machine himself; after that, `/api/state`
  `delivery.undelivered` should no longer list the two Windows meetings named
  in MEETONTRACK-136.
- MEETONTRACK-138 (Mac: a browser holding a silent output stream after the
  call blocks the no-call-audio stop, so such a recording still runs to the
  duration ceiling), MEETONTRACK-139 (Windows final transcription found
  `mic.wav` locked), MEETONTRACK-131, MEETONTRACK-132, MEETONTRACK-113,
  MEETONTRACK-118 and MEETONTRACK-85 remain.
- `swift-build` CI ran on the built revision `41fa12a`; the Swift tests ran
  locally.
- This Mac's GitHub tokens lack `workflow` scope; the pin commit touching the
  workflow was pushed from the devserver (from a bundle of the same commits).

## Explicit limits

No clean Mac and no audio hardware tests. Mac is ad-hoc signed and not
notarized; Windows is unsigned. No automatic installer is enabled. Never
restart an active recording to update.
