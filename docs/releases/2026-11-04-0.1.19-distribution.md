# Public MeetOnTrack 0.1.19 distribution acceptance

Date: 2026-11-04. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved building, publishing for Mac and Windows, updating the
website and installing on the owner's Mac on 2026-11-04. Same process as
[0.1.18](2026-11-02-0.1.18-distribution.md); this record lists what differs.

Contents: MEETONTRACK-94 (meeting reports are sent only from the recorder's
final transcript; a call whose final transcript is missing after an hour shows
"waits for the final transcript"; split meetings import their part of it) and
MEETONTRACK-117 (speakers corrected on the live text carry over to the final
transcript; corrections that cannot be placed ask to "check the speakers"),
with their review fixes. Branch `feat/one-app` (0.1.20) is not included.

## Immutable package identity

Both packages embed application revision `cfcca58`, built from a clean
worktree at that commit. `git diff v0.1.18..cfcca58 -- capture/` is empty, so
the Swift binary, Sparkle and LocalVQE were reused from the published 0.1.18
archive (same 3,901-file list; LocalVQE files byte-identical), assembled as
0.1.19 (build 441; the build number jumped because the recorder history was
merged into this repository).

This is the first Windows package whose recorder is built from the in-repo
`windows/` (MEETONTRACK-2):
[windows-candidate run 41842727295](https://github.com/AIAgentLbs/meetontrack/actions/runs/41842727295)
at `cfcca58` with version 0.1.19 ran the recorder core and live tests, built
`managed.zip` (SHA-256 `b9be625f...`) and accepted its own candidate. The
release archive was composed locally from that `managed.zip` with
`package_candidate.py` (capture revision `cfcca58`), as for 0.1.18. The
recorder sources equal recorder `50e7448` except the path of its version file;
the native component stays 0.6.6. Its `capture/` files differ from 0.1.18
because they were rebuilt and the .NET runtime moved from 10.0.13 to 10.0.14
(one runtime DLL renamed). `python/` and the native speech runtimes equal
0.1.18's. The CI-composed candidate has the same `capture/` and `python/`
files; only text files differ (CRLF on the Windows runner).

Commits: pins `b246cca`; Windows notes and `windows-v0.1.19` tag/target
`e7bc490a0c3a5a5aaa015af2be00491d571b9938`; Mac notes and `v0.1.19` tag/target
`20bf51926b89ff34b95b340a7e9b88fb13d260e2`.

## Update notice

0.1.18 service on the owner's Mac (`/api/updates`, technical-beta, macOS)
showed no newer release while the 0.1.19 releases were drafts. After

`https://github.com/AIAgentLbs/meetontrack/releases/tag/v0.1.19`, its notes,
and `notify: true`, so the header notice appeared. After the update the
service reports 0.1.19 with no newer release.

## Known gaps

- The Windows machine still runs 0.1.13.
- MEETONTRACK-120: Windows makes no PDF report, so no report is delivered
  there (inherited, found by this review).
- MEETONTRACK-118: a final transcript that never arrives stops being flagged
  after the 3-day delivery window. MEETONTRACK-119: rare cases of carrying
  speaker corrections remain.
- MEETONTRACK-106 and MEETONTRACK-108 from 0.1.18 remain.
- This Mac's GitHub token lacks `workflow` scope; the pin commit touching the
  workflow was pushed from the devserver (from a bundle of the same commits).
- Workflow artifacts expire after 30 days; the 0.1.19 `managed.zip` is
  reproducible from `windows/` at `cfcca58`, and 0.1.19's `capture/` files are
  the reference until then.

## Explicit limits

No clean Mac and no audio hardware tests. The final-transcript-only delivery
and speaker carry-over were checked by unit and UI tests, not by a real call.
Mac is ad-hoc signed and not notarized; Windows is unsigned. No automatic
installer is enabled. Never restart an active recording to update.
