## Owner's Mac

Capture was idle (no capture, no audio recording) and was quit through its
Apple Event, as the installer does for the in-app Install button; the
installer from Terminal refuses while Capture runs. `curl -fsSL
https://meetontrack.com/install.sh | bash` then installed 0.1.35, preserved
recordings and settings and reopened the app. `/api/health` reports 0.1.35.

`/api/agenda` answers `calendar_state` `failed` with `failed_days` 23.11 and
24.11 and no meetings; the agenda covers today and tomorrow only, so 26.11 is
not in it. Cause: the Mac's chosen Google profile is `personal` (gws named
profile), not the app's own sign-in, so the 183 path does not apply, and the
fallback runs bare `gws` (default profile) instead of `gws-personal`. The same
26.11 read through `gws-personal` returns 7 events. Follow-up:
MEETONTRACK-186.

`meetingcopilot permissions` from Terminal answers `microphone` and
`call_audio` `unknown`; not changed by this run (the owner grants them; see
MEETONTRACK-185).
