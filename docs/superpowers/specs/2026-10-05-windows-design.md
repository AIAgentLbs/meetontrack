# Meeting Copilot для Windows — спецификация

Дата: 2026-10-05. Статус: подход согласован владельцем; письменная спецификация
ожидает проверки. Этот документ не означает готовность Windows-релиза.

## Цель и границы

Поставить Meeting Copilot для Windows с тем же рабочим экраном, контекстом,
вопросами, рисками, архивом и доставкой отчётов. Не переписывать захват Swift:
использовать полученные исходники Amanu Windows как платформенную основу.
Первый целевой вариант — Windows 11 24H2+, x64; ARM64 и старые Windows не заявлять.
Это выбранная граница первой поставки, а не уже проверенная совместимость.

Сохранить постоянную работу, автоматическую запись и ручной запуск. Короткие
автоматически обнаруженные сессии менее пяти минут не становятся встречами:
до порога аудио хранится временно для продвижения в полноценную встречу.
Ручной запуск не подавляется этим фильтром. Не обещать восстановление аудио,
которое физически не было захвачено.

## Основа и варианты

Выбран вариант интеграции исходников: нативный C# захват + общий Python/web
Copilot. Альтернатива запуска неизменённого Amanu рядом не даёт надёжного
управления и live-контракта. Новый захват с нуля дублирует готовую работу.

Локально проверенная основа:
`~/.local/share/meeting-copilot/upstream/amanu-windows-v0.6.5`,
commit `7d45b672a132753d2e92034c4dce7e9ae816d282`.
В ней есть `LiveLineReady`, `LiveStatusChanged` и `LiveLine` с Id, At, Speaker,
Text, IsFinal, AudioThroughMs. MIT notices Andrew Jones и Samat Galimov сохранять;
все включаемые библиотеки и модели занести в third-party notices.
Подпись и update feed автора не использовать для изменённого приложения.

Работать от опубликованного общего кода v0.1.8 в отдельной ветке, не переносить
все незакоммиченные изменения macOS и не менять установленную Mac-систему.

## Компоненты и данные

1. `windows/`: исходники захвата, собственная идентичность приложения и адаптер
   экспорта. WASAPI microphone/system остаются разными каналами. Запись не зависит
   от модели, Python, Google или доступности анализа.
2. Общий backend: существующий `copilot/web`, с небольшим платформенным слоем
   путей, запуска процессов, управления Capture и обнаружения возможностей.
   На Windows не вызываются `osascript`, `open`, `launchctl`, Swift-помощники
   или macOS screenshot API. Неподдерживаемые возможности видимо недоступны,
   а не имитируют успешную работу.
3. Нативный supervisor запускает один web-процесс на loopback `127.0.0.1:43121`.
   Чужой процесс на порту не завершается: показывается конфликт.
   Повторный запуск открывает существующий экземпляр. Сбой web не останавливает
   аудио; повторный запуск ограничен backoff, без бесконечного быстрого цикла.
4. Данные: `%LOCALAPPDATA%/Meeting Copilot Data/{config,recordings,archive,reports,models}`,
   отдельно от заменяемых файлов установки. Секреты — Windows Credential Manager;
   личные настройки, OAuth и записи в пакет не включать. Mac-пути неизменны.

## Контракт live и управления

Экспортировать атомарно JSON version 1, совместимый с `LiveTranscriptExporter`:
meeting_id, title, status, started_at, updated_at, remote_attendees,
meeting_link, segments, capture_warnings, recording_dir,
recognition_progress_at, recovery_attempts. Время — UTC ISO8601; timestamp
реплики вычисляется от начала текущего логического звонка, не от запуска worker.
Стабильный upstream Id используется для замены provisional-реплики, не добавления
дубликата. Состояния: idle/loading/recording/paused/overloaded/model_missing/error/finished.
Факт записи и прогресс ASR публикуются отдельно: отставание ASR не означает остановку записи.

source сегмента — microphone или system по фактическому каналу. speaker/voice_id
заполняются только при наличии доказательств; системный канал сам по себе не
отличает нескольких удалённых участников. Не выдавать одно имя за диаризацию.

Управление start/pause/resume/finish проходит через локальный named pipe,
доступный только текущему пользователю. Команда имеет request_id и meeting_id;
повтор request_id идемпотентен. Ответ содержит принятое состояние либо явную
ошибку. Публичных HTTP-команд управления без проверки origin/token не добавлять.

## Надёжность и восстановление

Разрыв Zoom не завершает логический звонок автоматически. «Возобновить» сохраняет
UUID, вопросы, заметки, план и временную шкалу; новые фрагменты добавляются в ту же
встречу. Перед записью сегмента фиксировать его метаданные на диске, затем обновлять
live-проекцию. После аварии сверять файлы с журналом и продолжать незавершённую
встречу только по явному решению пользователя.

Аудио — первичный источник, распознавание — воспроизводимая производная.
Очередь ASR ограничена; при отставании сохраняется указатель на аудио для replay,
а не растущий RAM-буфер. Finished освобождает память модели/сессии согласно
настройкам, фоновые проверки неизменившихся файлов не повторяют полный разбор.
Доставка идемпотентна по meeting_id и версии отчёта; повторная попытка не означает
отправку нового письма каждый раз. Состояние показывается в приложении, без шума
«всё нормально». Google только по включённым источникам, один аккаунт; gws и
LLM CLI обнаруживаются в Windows PATH, Mac PATH не подставляется.

## Установка, обновление и ограничения

Windows runner собирает self-contained C# приложение, нативные ASR runtimes и
изолированный Python runtime с общим backend. Конечному пользователю не нужны
SDK, компилятор или системный Python. Модели — отдельная загрузка с размером,
checksum, прогрессом, повтором и отменой. Первый запуск спрашивает RU/EN, доступ
к микрофону, режим локальной/облачной обработки и источники контекста.

Velopack обновляет весь комплект совместимых native/web компонентов. Собственный
feed, отдельная Windows-версия пакета, manifest ревизии/хэшей и подписанный
установщик. Обновление только вне активной записи; данные не мигрируют разрушительно,
предыдущий комплект сохраняется для rollback. Автозапуск по выбору пользователя.
Не публиковать Windows-команду установки, пока нет реального проверенного артефакта.
Не брать чужие signing credentials; отсутствие нашей подписи — открытый release gate.

На первом этапе общий Google broker остаётся gws-based с явным подключением и
отключением. Много аккаунтов, новый OAuth-клиент и полный текст Drive не входят
в этот перенос; эти ограничения показываются в настройках. Offline — опция:
в этом режиме Google и облачные LLM/STT не вызываются. Телеметрию upstream
не включать скрыто: аудит сетевых вызовов и явное согласие перед включением.
Чат импортируется из доступных экспортов; автоматический доступ ко всем чатам
или определение каждого спикера на любой платформе не обещается.

## Приёмка и выпуск

Синтетические контрактные тесты: атомарность, UTC, provisional replacement,
повтор команд, тот же UUID после resume, ошибки записи, bounded queues,
порт/пути с пробелами и Unicode, отсутствие macOS-команд на Windows.
Общие backend и Mac-регрессии должны оставаться зелёными.

На настоящей Windows проверить чистую установку без SDK, RU/EN onboarding,
микрофон + системный звук, offline, потерю модели, принудительное завершение
worker/web, sleep/wake, разрыв и повторное подключение Zoom, replay хвоста,
архив и доставку. Двухчасовой звонок: сверить длительности и покрытие по обоим
каналам, все пробелы явно объяснить; несколько встреч и длительный idle:
замерить process-tree RAM/CPU/I/O, отсутствие роста от встречи к встрече.
Проверить update/rollback и сохранность пользовательских файлов по хэшам.

CI-сборка не заменяет эту аппаратную приёмку. Установщик, хэши, точная ревизия,
подпись и результаты Windows-проверок — обязательные доказательства выпуска.
Доступность Windows-машины и собственной подписи пока не подтверждена;
при отсутствии этих условий подготовку можно продолжать, готовность релиза — нет.
